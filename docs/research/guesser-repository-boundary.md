# Standalone DrawbackGuesser repository boundary

Status: reviewed dependency and change-impact analysis.

## Decision

Create `tetizz/DrawbackGuesser` as a TypeScript/Python monorepo that owns
prediction, training, evaluation, browser inference, and model-release
governance. It must not become a second authority for drawback legality.
`DrawbackEngine` should publish a pinned, offline-bundleable rule-runtime and
public-position-authority release that the guesser consumes.

The split is viable, but a direct file copy is not dependency closed today:

- `packages/predictor/src/catalog.ts` imports the complete executable rule
  universe from `@drawbackengine/drawback-engine`;
- `packages/predictor/src/predictor.ts` and `observation.ts` call public
  position-authority functions from `@drawbackengine/chess-core`;
- the browser PGN path imports
  `@drawbackengine/chess-evaluator/completed-pgn-sidecar`, whose current
  package manifest also depends on the full drawback search/evaluator stack;
- `@drawbackengine/chess-core` exports public replay code and authoritative
  game-session code from one package and compiles both.

Copying those packages into both repositories would work temporarily but would
create two rule authorities. The required order is therefore:

1. split and publish the engine contracts from `DrawbackEngine`;
2. create the dependency-closed guesser repository against an exact engine
   release;
3. move prediction and ML ownership;
4. leave compatibility re-exports in the legacy host repository for one deprecation
   window;
5. delete duplicate predictor/ML code from the legacy host only after
   cross-repository parity is green.

## Proven dependency graph

`pnpm -r list --depth -1` reports eleven workspace projects. The relevant
compile/runtime path is:

```text
browser PGN/live inference
  -> predictor
     -> shared contracts
     -> public position authority
     -> executable prediction rule universe
  -> browser neural artifact parser/runtime
  -> rank-preserving fusion
  -> completed-PGN replay
  -> completed-PGN evaluator-sidecar verifier (optional, uniformly present)

Python training/evaluation
  -> strict dataset consumer contract
  -> public feature encoder
  -> symbolic vectors generated by the TypeScript predictor
  -> PyTorch model/checkpoint/browser exporter
  -> held-out evaluation and release governance
```

The following are proven direct dependencies, not architectural guesses:

| Consumer | Current authoritative dependency |
| --- | --- |
| `packages/predictor/src/types.ts` | drawback rule types, public authority snapshot, player color |
| `packages/predictor/src/predictor.ts` | rule filtering/state transition, public authority legal moves and transitions |
| `packages/predictor/src/catalog.ts` | all exact, parameterized, rerandomized, and evaluator-backed rule implementations |
| `apps/web/src/pgn-analysis.ts` | completed PGN replay, symbolic predictor, sidecar constraints, neural runtime, fusion |
| `apps/web/src/live-prediction.worker.ts` | public observation constructor and independent White/Black symbolic state |
| `ml/training/drawback_ml/records.py` | strict public-feature/label separation and schema-6 symbolic arrays |
| `ml/training/drawback_ml/corpus_contract.py` | authenticated manifests, replay, evaluator schedule, split contract |
| `ml/evaluation/runner.py` | training record/inference contracts and held-out metrics |

`probe-search`, `drawback-search`, Stockfish process orchestration, self-play
agents, rule fixtures, and the interactive game board are not dependencies of
the core guesser. Diagnostic move search is a separate optional product
capability and should not expand this initial repository boundary.

## Target repository layout

The target layout should be:

```text
apps/
  web/                         # post-game and explicitly offline inference UI
packages/
  engine-client/               # pinned engine release adapter and compatibility checks
  predictor/                   # symbolic/Bayesian predictor
  inference-web/               # browser model parsing, workers, fusion, reports
  dataset-contract/            # consumer-only schemas and provenance validation
  shared/
ml/
  training/
  evaluation/
scripts/
  generate-v22-cross-runtime-fixture.py
docs/
  architecture/
  research/
```

`engine-client` is a local adapter around published packages. It does not
contain copied drawback filters. `dataset-contract` validates data produced by
the engine repository; it does not simulate games.

## Cross-repository engine contract

### Published packages

`DrawbackEngine` should publish immutable releases of:

1. `@drawbackchess/rule-contract`
   - `ChessMove`, `PositionView`, `RuleEvidence`, `PositionAuthorityId`;
   - exact and external-constraint rule interfaces;
   - no rule implementations and no secret snapshots.
2. `@drawbackchess/rule-runtime`
   - executable rule implementations;
   - a `createPredictionRuleUniverse()` adapter returning exact,
     parameterized, rerandomized, and external-constraint hypothesis
     descriptors in canonical order;
   - strict parameter validators and declared authority compatibility.
3. `@drawbackchess/public-position-authority`
   - canonical standard-chess and capturable-king snapshots;
   - complete public legal move generation and transition;
   - completed-PGN replay.
4. `@drawbackchess/evaluator-sidecar-contract`
   - canonical request and cache-record validation;
   - authenticated completed-PGN sidecar validation;
   - no process launch, UCI transport, engine score, PV, or cache timing.

These packages must work offline in the browser build. The guesser must not
call a network rule service during inference.

### Release descriptor

Every engine release must include canonical JSON with at least:

```ts
interface EngineReleaseDescriptorV1 {
  readonly format: "drawbackchess-engine-release";
  readonly version: 1;
  readonly sourceRevision: string;
  readonly packageVersions: Readonly<Record<string, string>>;
  readonly packageIntegritySha256: Readonly<Record<string, string>>;
  readonly catalogSha256: string;
  readonly ruleIds: readonly string[];
  readonly standardPgnRuleIds: readonly string[];
  readonly unsupportedObservedRuleIds: readonly string[];
  readonly predictionUniverseVersion: number;
  readonly symbolicFeatureVersion: number;
  readonly symbolicRuleIds: readonly string[];
  readonly positionAuthorityIds: readonly string[];
  readonly evaluatorPolicyIds: readonly string[];
}
```

The current declared universes are 182 supported rules for the prepared
evaluator view and 180 for ordinary standard-PGN browser analysis. The two
evaluator-fact rules must be reported as unavailable when there is no uniform,
authenticated sidecar; they are neither unrestricted nor eliminated.

The guesser lockfile pins exact package versions and integrity. Every dataset,
checkpoint, browser artifact, evaluation report, and release receipt records
the engine descriptor digest, catalog digest, ordered symbolic rule digest,
position-authority version, and evaluator policy when present.

### Compatibility requirements

An engine upgrade is accepted only when:

- the canonical rule-ID and parameter-particle universe is explicit;
- all golden observations produce identical ordinary legal sets, hypothesis
  hard masks, and transitions unless the release declares an intentional
  contract change;
- standard and capturable-king public traces replay identically;
- parameter canonicalization and rerandomized marginalization remain stable;
- TypeScript symbolic vectors match the Python schema order and digest;
- every intentional hard-mask change triggers dataset and model compatibility
  review rather than silently reusing an old checkpoint.

## Dataset boundary

Simulation and label generation remain engine responsibilities. The guesser
receives content-addressed artifacts and validates them before training.

The current `DatasetMove` is a combined storage record. The consumer must split
it immediately into three typed domains:

```text
PublicFeatureRecord
  fenBefore, observed move, move number, ply, mover color, prior public SAN,
  complete ordinary legal moves, public clock, public symbolic probabilities,
  public hard masks, optional uniformly collected evaluator constraint

TrainingLabelRecord
  true drawback, hidden parameters, trigger target, drawback-legal mask target

EvaluationMetadata
  bot agent/style/strength and content-addressed game/split provenance
```

The join key may be used by the trusted training loader but is not a model
feature. Prefer a future schema with separate public-feature and label streams,
or at minimum nested `public`, `labels`, and `evaluation` objects with strict
exact-key parsers. Unknown fields fail closed.

Required artifact rules:

- training, validation, and sealed-test games are disjoint by complete game
  seed and content hash;
- validation sub-partitions for selection, calibration, and gate remain
  disjoint;
- the sealed-test manifest and bytes are unavailable to training, tokenizer
  fitting, parameter vocabulary, epoch selection, calibration, and error
  analysis;
- every split manifest binds dataset byte length/SHA-256, row and game counts,
  scheduled outcomes, engine release, catalog, evaluator, symbolic schema,
  and source revision;
- evaluator facts are either uniformly present under one pinned public policy
  for every eligible row or absent from the whole view;
- generated NDJSON/Parquet files never enter Git.

`ml/training/drawback_ml/records.py`, `corpus_contract.py`,
`semantic_replay.py`, `training_corpus_set.py`, and their tests are the
authoritative consumer implementation at this revision. Engine-side
`packages/simulation/src/dataset.ts` remains the producer reference.

## Model artifact boundary

Source-controlled:

- model architecture, feature encoder, losses, deterministic training code;
- checkpoint and release schemas;
- tiny synthetic/golden parity fixtures;
- content-addressed manifests and approval schemas with no private data.

External release artifacts:

- corpora and split-private manifests;
- PyTorch checkpoints and checkpoint indexes;
- ensemble, selection, calibration, and approval receipts;
- exported browser model JSON;
- real-domain prediction bundles and any completed PGNs.

Large artifacts belong in access-controlled object storage or explicit GitHub
release assets, addressed by SHA-256. A browser artifact may be bundled into a
release only after its source checkpoint, ensemble selection, calibration,
engine descriptor, and browser parity receipt are recursively authenticated.
The web application does not download arbitrary model URLs or execute
artifact-supplied code.

## Anti-leakage invariants

The following are release-blocking:

1. `trueDrawback`, `hiddenParameters`, `drawbackInternalState`,
   `drawbackLegalMoves`, `ruleTriggered`, `forced`, and `result` cannot enter a
   feature parser. Bot identity/style/strength are evaluation-only.
2. Model inputs are allowlisted. Unknown keys and plausible aliases fail
   closed instead of being ignored.
3. Ordinary public legal moves are allowed; drawback-filtered legal moves are
   labels only.
4. Symbolic probabilities and masks are regenerated solely from authenticated
   public positions, complete legal sets, public history, and uniformly
   available public evaluator facts.
5. Hard legality is applied after every neural or calibration transform. A
   symbolically eliminated hypothesis remains exactly zero forever.
6. White and Black predictor states, masks, labels, and heads remain isolated.
   An observed move updates only the mover's hypothesis state.
7. Features for ply `n` cannot read a later move, final position, result, or
   post-game reveal.
8. A color receives classification supervision only after that color has made
   at least one publicly observed move.
9. Missing evaluator facts make evaluator-dependent hypotheses unavailable;
   absence cannot be a class-correlated feature or be interpreted as ordinary
   legality.
10. Training truth may select a loss target and evaluation truth may score a
    report, but neither may change the analytical prediction payload/digest.
11. Simulation seeds, split names, game IDs, worker IDs, cache hits, evaluator
    latency, scores, and PVs are not model inputs.
12. Completed real-domain inference and revealed labels remain two separately
    authenticated stages. No live external-game collection or assistance is
    part of this repository.

## CI matrix

The standalone repository should replace the current monolithic CI with the
following required jobs:

| Job | Matrix | Release-blocking checks |
| --- | --- | --- |
| Node static | Node 22, pnpm lockfile frozen | workspace listing, strict typecheck, ESLint, build |
| TypeScript unit | Node 22 | predictor math/state isolation/authority tests, browser protocols, artifact parsers, fusion |
| Engine contract | pinned engine release plus proposed upgrade in compatibility PRs | package integrity, descriptor/catalog/schema digests, golden legal-set/mask/transition parity |
| Python unit | Python 3.11 and 3.12 | training/evaluation tests excluding intentionally sealed data |
| ML CPU smoke | Python 3.12, pinned CPU PyTorch and `python-chess` | tiny deterministic train, checkpoint load, inference, browser export, held-out evaluation |
| Cross-runtime parity | Node 22 + Python 3.12 | Python/browser feature, tensor, residual, hard-mask, fusion, and v22 golden parity |
| Leakage negative | Node 22 + Python 3.12 | inject every forbidden field/alias, future-ply data, opposite-color labels, mixed evaluator presence |
| Corpus contract | synthetic content-addressed fixture | replay, manifests, split overlap, outcome ledger, evaluator uniformity, no-clobber writes |
| Browser worker | Chromium plus Node unit harness | model authentication, worker correlation/cancellation, completed-PGN bounds, symbolic-only vs hybrid provenance |
| Release governance | Python 3.12 | selection/calibration/gate separation, checkpoint indexes, sealed-test authorization, reproducible report |
| Dependency/license | lockfile | known-vulnerability and license policy; reject local/path dependencies in a release tag |

CI must not require a private corpus or a model checkpoint. Promotion runs in a
separate, authorized workflow using explicit content-addressed inputs. It must
never open the sealed test on an ordinary pull request.

The current `.github/workflows/ci.yml` is useful as a bootstrap because it
already runs Node and Python validation, cross-runtime fusion math, full
training/evaluation unit suites, and compile checks. Its rule-catalog evidence
job belongs in `DrawbackEngine`; the guesser replaces it with the engine
contract job.

## Migration tests and exit criteria

The move is complete only when:

1. the old and new symbolic predictors produce byte-equivalent White/Black
   posteriors and evidence for the frozen observation fixtures;
2. hard-elimination and color-isolation property tests pass against the
   published engine packages;
3. all existing Python training/evaluation tests pass from the new import root;
4. all four browser artifact formats retain Python/browser golden parity;
5. a completed PGN produces the same analytical digest, coverage, timeline,
   and final rankings in both repositories;
6. a synthetic corpus passes both the engine producer audit and the guesser
   consumer audit;
7. no target source file imports `@drawbacktrainer/simulation`,
   `@drawbacktrainer/drawback-search`, a UCI process transport, or a player
   secret/session snapshot;
8. repository and release secret scans find no corpus, checkpoint, PGN,
   credentials, or private manifest;
9. legacy compatibility imports point to the released guesser
   package rather than retaining a second predictor implementation.

## Risks and unresolved decisions

- **Packaging is the immediate blocker.** All current workspace packages are
  private source exports. A versioned publication mechanism and namespace must
  be selected before the standalone build is reproducible.
- **Catalog ownership is coupled.** `DEFAULT_HYPOTHESIS_RULE_IDS` and the
  Python symbolic schema duplicate a canonical order. The engine descriptor
  and generated bindings should replace hand-maintained cross-repository
  copies.
- **Public authority is not FEN-only.** Capturable-king castling king-passant
  state requires the complete public snapshot; simplifying to FEN would make
  hard elimination unsound.
- **Standard PGN covers 180, not 182, supported rules** unless a uniformly
  authenticated evaluator sidecar is supplied. Product copy and metrics must
  preserve “unavailable” separately from “eliminated.”
- **Legacy browser artifact formats use different fusion equations.** They
  remain compatibility paths; new promotion should prefer the authenticated,
  rank-preserving ensemble path.
- **Dataset wire format is still combined.** The current Python parser creates
  a strong in-process separation, but separate feature/label streams would
  reduce accidental leakage and should be a schema-versioned follow-up.
- **Diagnostic search is deliberately excluded.** If the standalone product
  later owns information-gain recommendations, migrate `probe-search` in a
  separate dependency/assurance review; do not smuggle it in through the first
  guesser split.
- **Repository naming is unresolved.** Published package names should not
  imply that `DrawbackGuesser` owns game legality. The examples above use the
  neutral `@drawbackchess/*` namespace, subject to maintainer approval.
